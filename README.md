# 墨笺 · AI 长篇小说创作工作台

面向长篇小说的单用户本地创作工作台：把**人物档案、世界观设定、剧情蓝图、章节正文与版本、章节记忆**放在同一处，让两个 AI Agent（**策划**与**写作**）围绕同一部书协作——策划陪你定走向、起草设定与蓝图、审稿并补充要求，写作把蓝图写成正文；结构性改动先进入「待确认」，正文全程版本快照、可回滚。

当前版本：**1.0.11**

- 后端：Spring Boot 3.5 + MyBatis-Plus + MySQL 8（Redis 可选）
- 前端：Vue 3 + Vite + Pinia + Vue Router，自研 v3 设计系统（暗色「墨海」/ 亮色「素笺」）
- 模型：任何 OpenAI 兼容接口（任意服务商 / 本地网关），Key 以 AES-GCM 密文落库，只回显掩码

## 核心能力

### 双 Agent 协作

| | 策划 Agent（PLANNER） | 写作 Agent（WRITER） |
|---|---|---|
| 职责 | 人物、设定、剧情蓝图；给多条走向供选择；审稿与补充要求 | 按本章蓝图 / 写作要求把蓝图写成正文 |
| 工具 | 23 个：资料查询、起草/修改/删除人物设定蓝图、方案选择、建章、改章节名、撤回写作指令、审稿、补充要求、章节状态、查看写作对话等 | 8 个：资料查询、正文读取、写作/修改、补充要求执行、删章申请等 |
| 模型 | 可独立配置（默认更稳的模型） | 可独立配置（默认更强的写作模型） |

- **薄运行时**：`AgentLoopService` 手写「想 → 做 → 看 → 再想」循环，约 240 行，不依赖框架，可脱离 Spring 单测。
- **上下文工程**：全量优先 + 自适应预算 + 严格优先级裁剪；超限时从服务端错误里自动学习模型真实上下文上限；界面实时显示主副两套上下文的装填比例。
- **人工确认闸门**：人物、设定、蓝图的 AI 增改先写 `agent_draft`，用户点「确认采纳」才进入业务表；开启自动采纳时只自动采纳**本轮新产生**的草稿，旧草稿继续等待确认。
- **删除也要确认**：策划删除人物/设定/蓝图只生成待确认申请，作者在待确认区点确认后才真正删除。
- **审稿闭环**：策划可查看正文、写作要求、补充要求执行状态和写作会话，追加/移除补充要求；写作按条执行并保存后先标记「待核验」，作者确认落实才变为「已核验」，失败/打回则回到待执行。策划下发的写作指令在未执行前可以撤回。
- **多服务商**：可同时接入 DeepSeek、OpenCode Go 等多家服务商；模型库按服务商分组，策划和写作可以分别选择任意已配置服务商的模型。
- **可观测**：每次运行记录步数、工具轨迹、token、耗时（`agent_run`）；用量与花销按公开定价估算并展示在「模型接入」页。

### 写作工作台

- 策划模式：对话流、思考过程（三档显示）、工具调用轨迹、故事走向卡（可关闭/发送自动收起）、待确认草稿审阅、引用资料对话。
- 写作模式：左侧与写作 Agent 连续对话（跨章记忆），右侧纸面流式正文；正文可编辑、标记完成、版本对比与回滚、章节记忆编辑、关联本章蓝图。
- 正文/对话支持右键「引用这段」：引用块与手打内容分开展示，长引用可折叠，发送时拼成结构化的修改依据。
- 切换页面/项目/会话不会终止写作任务；返回后通过 active-task 重新连接。策划请求切走后也会在回来时轮询恢复回答。
- 输入框草稿按「项目 + 会话/章节」自动保存在浏览器本地，页面意外刷新、Vite 热更新或切走再回来都不会丢未发送内容。
- 长篇连续性：写作成功后自动在后台提炼**章节记忆**并写回，下一章作为前情注入。
- 视觉输入：支持识图的模型可以直接把图片作为策划/写作输入，图片不会写入历史记录。
- 首次使用指南：左侧栏「指南」或命令面板打开，六步说明双 Agent 分工、模型配置、草稿采纳与审稿流程，面向没用过 Agent 的新读者。

### 其他

- 版本不可变：每次保存/生成都产生快照，回滚＝新建一个快照，历史全部保留。
- 导入导出：整本小说 JSON 导入导出（可勾选片段），导出 Markdown / TXT 成书。
- 模型接入设置页：服务商预设、多服务商独立 Key、按服务商分组的模型库、双角色模型配置、用量花销。
- 成书页：沉浸式阅读、目录、阅读进度、导出。

## 快速开始

环境：JDK 17、Maven 3.9、Node 22+、MySQL 8。

```bash
# 1. 建库
mysql -u root -p < init.sql

# 2. 建表（幂等；应用启动时也会自动补齐 Agent 相关表）
mysql -u root -p mojian < src/main/resources/schema.sql

# 3. 配置数据库（可用环境变量覆盖，默认 root/123456）
#    见 src/main/resources/application.yml

# 4. 启动后端（8081）
mvn spring-boot:run

# 5. 启动前端（5173，/api 代理到 8081）
cd web && npm install && npm run dev
```

打开 `http://localhost:5173`：首页 → 新建作品 → 进入工作台；在「模型接入」页填 Base URL / API Key / 模型后即可对话（未配置时后端会走演示模式，Agent 能力不可用）。

## Agent 设计要点（为什么这么做）

1. **自研薄运行时，而不是引框架**：业务难点是跨请求持久记忆、双 Agent 交接、无 embedding 时的上下文策略，框架不解决这些；自研部分只有几百行且有测试锁住。
2. **全量注入 + 超限裁剪，而不是一上来做 RAG**：当前一本长篇的完整材料约十万 token 级，而模型窗口 100 万；装得下就全给（筛选必然丢东西）。预算到 80% 左右再引入检索。
3. **写操作走草稿表**：AI 能改结构（人物/设定/蓝图）这件事必须有闸门；正文则由版本快照兜底，所以正文直接写章节。
4. **写作任务落库**：`generation_task` 的 `(chapter_id, active_slot)` 唯一索引保证同一章同时只有一个活动任务，服务重启后僵尸任务会被回收成 FAILED。
5. **取消有确定性标记**：不依赖线程中断，循环在每步前与每次工具执行前检查取消标记。

## 配置

| 环境变量 | 说明 |
|---|---|

## Docker

```bash
cp .env.example .env       # 可选，按需改数据库密码 / 模型配置
docker compose up -d --build
# 前端 http://localhost （只绑定 127.0.0.1）
# 后端接口 http://localhost:8080 （只绑定 127.0.0.1）
```

Docker 路径适合“本机一键启动”；本机开发仍建议直接用 IDEA / Maven + Vite。前端镜像使用 Node 22 构建，后端镜像使用 JDK 17。

## 评测

`scripts/eval/` 提供一套可重复的评测：

- `dataset.json`：30 条任务型用例（寒暄、资料查询、方案结构、设定一致性、禁止虚构等）。
- `run_eval.py --offline`：不花钱的结构评测（上下文装填、预算、章节范围、蓝图去重等）。
- `run_eval.py --live`：调用真实模型，按规则评分（会消耗额度）。

## 已知边界

- 单用户、本地优先，没有账号体系；请只在本机 / 可信内网运行。
- 未引入向量 RAG；当前优先全量注入，超预算时用词面检索兜底。
- 评测为规则评分，暂未引入 LLM Judge。
- 前端视觉与功能以 v3 为准，旧页面已退役。
